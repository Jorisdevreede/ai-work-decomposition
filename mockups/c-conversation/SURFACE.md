# Conversation first

Operate mode. The supplied fleet brief fixes the concept, all eight screens, content and browser sizes. This is an app surface built directly in code.

## Direction contract
THESIS: A conversation turns into a shared, inspectable picture of the team. The agent leads; the canvas records.

OWN-WORLD: Forest green conversation surface, white working canvas, sage selection, coral used only for people-focused capacity. A familiar system sans, compact tables, generous section spacing, single-stroke SVG icons.

STORY: Femke starts from an imperfect team description, checks the extracted roster, sees what she will leave with, then strengthens the draft with her team's input.

FIRST VIEWPORT: A 68px masthead, 354px conversation column and a broad canvas. The canvas has route navigation, three input choices and an editable six-role roster. The primary action confirms the roster and opens the goal. On phones a labelled Conversation/Canvas switch makes both views reachable.

FORM: Brief-pinned direction C; no alternative concept selection. Signature interaction: the agent runs card sorting in the conversation; each answer advances the canvas and counts the chosen priorities. Canvas review edits update the agent’s recap before saving. Two guided North Star conversations also add visible evidence to the goal. Strategic assumptions draws out beliefs, fears and hype. Metrics inventory flags activity measures for review. Each guided conversation ends with an editable draft, an apply gate and links to the parts it changed. Short state-change transitions, no entrance sequence.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## UX acceptance
- Progressive disclosure → filter → approach details and module contents expand in place → the main route stays scannable.
- Recognition over recall → meaning → named people, tasks and systems remain visible → a lead can check the roster without remembering the source.
- Feedforward → meaning → each module states the goal output it fills → users know the result before starting.
- Cognitive load → act → one task card and three clearly labelled piles → the module needs one decision at a time.
- Goal gradient → act → completed cards and goal evidence are explicit → progress is tangible.
- Fitts's Law → act → 44px phone controls and reachable view switch → controls work at 390px.
- Provide exit points → memory → module completion states exactly what was added, with links to goal and role twin → no dead end.
- User control → act → editable assumption maps and metric classifications, with a separate apply action → agent suggestions remain drafts until reviewed.
